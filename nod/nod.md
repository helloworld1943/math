# Nod: a small language built as a Node graph

This replaces the previous `nod/` experiments. It is an executable initial
language, not a dependent-type kernel. Layers 1-3 are not used or modified.

## Run the playground

From the repository root, with Python 3.10 or newer:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r nod/requirements.txt
.venv/bin/python -m nod.server
```

Open **http://127.0.0.1:8765**. To select a different local port:

```sh
.venv/bin/python -m nod.server --port 8766
```

The [HTML editor](./playground.html) needs this server: opening it as a
`file://` document does not run the Python backend. Source edits automatically
tokenize, compose the graph, type-check, and execute after a short debounce.
The page shows ordered tokens, the real graph, node byte values, semantic
annotations, and output. Toggle token nodes to see the full lexical graph.
On error, the page explicitly retains the previous successful graph/output.
The initial source is [example.nod](./example.nod).

### Separate tokenizer and grammar pages

- **http://127.0.0.1:8765/tokenizer.html**:
  [tokenizer.html](./tokenizer.html) shows lexical rule definitions as Node
  graphs (category, pattern, priority, emit/skip), plus editable source and
  generated token occurrences. `int x=;` tokenizes successfully; grammar is
  not checked here.
- **http://127.0.0.1:8765/grammar.html**:
  [grammar.html](./grammar.html) shows grammar categories, alternatives,
  ordered symbol sequences, and composer actions as Node graphs, plus the
  syntax graph produced from the token stream. `int x=true;` and
  `print(unknown);` parse successfully here; semantic checking and execution
  are deliberately not run.

The rule diagrams are generated by [rules.py](./rules.py) from Lark's actual
compiled terminals and productions, not a separately maintained list.
The source excerpts show the original EBNF; the node diagrams show its
compiled alternatives, with generated repetition helpers available through
a checkbox. A quoted keyword in the grammar is included as its actual
implicit terminal definition.

Recursive grammar categories use shared category-symbol nodes. These
symbols name categories; they do not point forward to their own rule
definitions. “Open related rule” performs that lookup as navigation, not a
cyclic graph edge. Rule graphs are read-only visual projections; the parser
still consumes the Lark specification, not those projections.

Each selected rule diagram shows its reachable subgraph, preserving actual
graph-local IDs and positions. Definition and source-example graphs are
separate. Clicking their nodes reveals real byte values and output slots.
Moving between stage pages transfers source via the URL fragment and
builds a fresh graph; it does not persist handles across requests.

The stage endpoints are `GET /api/rules`, `POST /api/tokenize`, and
`POST /api/parse`. The latter two accept `{"source":"..."}`. Lexical errors
are still rejected by both stages. Types and runtime are handled only by
the full playground's `POST /api/run`.

## Example

```text
int count = 5;
bool x = true;
bool z = x | x;
print(z);

func xx(bool a, bool b) bool {
    return a && b
}

print(xx(z, false));
print(count + 2 * 3);
```

Output:

```text
true
false
11
```

The earlier proposed `int x=5; bool x=true;` is rejected: declarations cannot
reuse a name in the same scope. Nested blocks may shadow outer variables.

## 1. Node values belong to the foundation

The [Node layer](../node/readme.md) now supports:

```python
from node import Graph

graph = Graph()
literal = graph.create_node(value=bytearray(b"123"))
graph.edit_link(literal, 0, graph.root)
snapshot = graph.commit()
assert literal.value == b"123"
```

`Node.value` is immutable `bytes | None`. Byte arrays are copied at creation.
`None` means vacant and differs from `b""`. Bytes have no intrinsic encoding
or language type in the Node foundation. The existing ordering, fixed-slot,
no-duplicate-target, required-output-0, identity, and snapshot rules remain.
No global interning rule is added to Node.

## 2. Three language-building responsibilities

### Tokenizer

Raw source is scanned according to [grammar.lark](./grammar.lark). Each token
occurrence creates a node with raw UTF-8 spelling in `Node.value`, plus an
exposed category such as `NAME`, `INTEGER`, or `PLUS`/an operator terminal.
Actual terminal names are shown in the page; punctuation terminals may have
parser-generated names. Whitespace and `//` comments are skipped.

The source `int x=5; print(x);` contains two separate occurrences of `x`.
They keep their source order and locations; this lab does not merge token
occurrences merely because their spellings match.

### Grammar composers

Each uniquely named grammar rule/alias has a prescribed child arrangement.
The tokenizer's token stream is fed to Lark's interactive LALR parser.
Reduction actions call `Composer.compose` immediately, passing child node
handles. There is no separate full parse-tree/AST pass. Lark may
use temporary helper lists/trees for EBNF repetitions internally.

Composers match token categories and syntax structure, not literal payload
values. An addition description records the operand/operator parts, without
computing the sum. Non-token syntax nodes have vacant values.

Logical children map to real ordered output slots. Slot 0 points to root;
remaining targets are deduplicated to obey the Node no-duplicate rule.
`childSlots` explicitly records repeated logical roles. The graph's final
`Program` node reaches both the syntax and the complete `TokenSequence`, so
even punctuation token nodes remain reachable.

Structural categories, source locations, and logical child-role maps are
Nod metadata in `Description`, not additional Node foundation semantics.
Every logical child is represented by a real graph link. Category-specific
nodes with identical children may be reused within one parse. This is not
global canonicalization across requests.

### Semantic/type checker

`Checker` resolves names and checks declaration, assignment, function,
operator, condition, argument, and return compatibility. Parsing an expression
does not claim it is typed. Functions are registered first, permitting
forward calls and recursion.

Resolved declaration references and inferred types are read-only exported
annotations. They are **not extra graph output links**: forward-recursive
function bindings cannot be backward-only syntax edges. The immutable
syntax graph and the context-dependent semantic binding table are separate.
This replacement intentionally drops the old requirement to add a direct
output edge for every checker read.

## 3. Execution

`Runtime` interprets the checked node descriptions. It does not evaluate
source as Python or JavaScript. Runtime variable frames are separate from
immutable token bytes and syntax nodes.

Supported:

- `int` and `bool` declarations, assignment, lexical block scopes.
- Integer `+ - * / %`, unary `+ -`, comparisons, equality.
- Boolean `!`, `&&`, `||`, `&`, and `|`. Single `&`/`|` are eager Boolean
  operators, not integer bitwise operators. Double operators short-circuit.
- Parentheses and conventional precedence; binary operators associate left.
- `print(expression);`, which outputs lowercase `true`/`false` or decimal ints.
- `func name(type parameter, ...) type { ... }`, calls, recursion, and return.
- `if (condition) { ... } else { ... }` and `while (condition) { ... }`.
- `//` line comments. Statements require semicolons except `return`, where a
  semicolon is optional to support the requested function example.

Functions have their own parameter/local scope and can call other functions;
they do not implicitly capture top-level runtime variables. Pass such values
as arguments. Parameter names are unique; locals cannot redeclare parameters
in the function's outermost body. Every function must structurally return on
every path; an `if` requires both branches to return, and loops do not prove
termination or guaranteed return.

Integer division truncates toward zero. Remainder is defined by
`a == (a / b) * b + a % b`. Division by zero is an explicit runtime error.
Python's `bool`/`int` subtype relationship is not inherited: language
Booleans are not accepted as integers by the checker.

## 4. Errors and limits

Every request builds an isolated private graph. No graph or buffered print
output is returned unless parsing, checking, and execution all succeed.
Errors include stage and source location. The page labels previous successful
results explicitly when the current source is rejected or still pending.

The demo limits source to 32,000 characters, 5,000 tokens, source nesting
to 80 levels, literal length to 256 digits, graph size to 12,000 nodes,
runtime work to 20,000 steps, call depth to 64, and integer results to
4,096 bits. Limits are explicit errors, not a termination proof.

This is a bounded local demonstration, not a sandbox for arbitrary Python
callbacks or an unrestricted runtime. The server binds only to loopback,
serves an allowlist of assets, and does not provide host I/O to the language.

## 5. Tests

```sh
.venv/bin/python -m unittest node.test_layer0 node.test_animation nod.test_language nod.test_stages nod.test_server
```

The tests cover node values, original graph behavior, the example, parsing,
precedence, binding and type errors, scopes, functions, recursion, control
flow, runtime failures, limits, real graph links, full final-node reachability,
token order, and HTTP behavior.

Not implemented: dependent types, polymorphism, strings, collections, closures,
first-class functions, function overloading, `for`, imports, persistent graph
editing, incremental recompilation, or global canonical sharing.
